## 1. 本轮目标

   - 新任务检测/规划失败时明确失败，不继续显示旧结果；

2. 建立三个手工设定的规划模拟案例。

4. 在「③ 巡检规划」增加“规划案例对照（模拟输入）”，与录音检测状态分开保存。

## 4. 规划规则（D）

- 只把 `status="suspected_anomaly"` 的设备作为检查目标；
- `normal` 不加入目标；
- `invalid_input` 提示补录，不能当成正常，也不加入目标；
- 重要等级先高后低；在满足“等级不升高”的顺序中，选择路网累计距离最短者；
- 距离按 `scene/edges.csv` 的 `length_m` 用最短路径计算，不用直线距离；
- 从 `start_node` 出发，不强制回到起点；
- `priority` 是优先级清单，`visit_order` 是实际访问顺序；
- 状态：`ok` / `partial` / `no_targets` / `invalid_input`；
- 不可达目标保留在 `unreachable_asset_ids`，不进入 `visit_order`；
- 全部异常目标都不可达时仍是 `partial`，访问顺序为空、距离为 0。

## 5. 固定顺序基线

- 重要等级降序，同等级按设备编号升序；
- 与优化方案使用同一起点、同一批可达目标、同样的重要等级约束、相同的开放通道；
- 不强制返回起点；
- 距离由 D 的路网最短路实际计算，不写死 70 / 90 等数字。

## 7. 页面状态隔离

## 11. 第二轮增量：巡检执行（模拟）

补丁：`CD-R2-20261025`

### 11.1 目标

增加独立的巡检执行任务，记录：

- 任务编号、来源、创建时的检测输入快照；
- 最初的异常目标；
- 当前位置、已完成设备、待检设备；
- 当前关闭通道、累计已走距离；
- 当前剩余规划；
- 操作事件记录。

“待检设备”必须包括尚未完成的不可达设备，不能因为不可达就从总任务中消失。

### 11.2 任务来源

任务可以从两类来源创建：

1. 当前有效录音检测结果（保留 mock/real 和输入指纹）；
2. C1/C2/C3 手工模拟案例（保留案例编号和“不是 A 的录音检测结果”声明）。

两类来源分别保存；模拟任务不覆盖 A 的检测结果，导出 JSON 保留 `source.kind / label / is_mock / case_id / detection_snapshot`。

关联输入或检测结果集变化时，任务显示失效并要求重新创建，不静默套用新数据。

### 11.3 行走与确认

- `step_forward` 每次只能走到当前剩余路线的下一个相邻节点；
- 只能通过 enabled=true 且未被任务关闭的通道；
- 距离按该通道 `length_m` 增加；
- 没有“直接修改当前位置”的接口；
- 到达待检设备节点但尚未确认时，不能继续前进一步；位置和里程保持不变；
- `confirm_asset` 只在当前节点等于设备节点、且设备在待检列表中时成功；
- 确认还遵守等级约束：仍有更高等级的可达待检目标时，不能先确认低等级设备；
- 重复确认同一设备报错，不重复统计；
- 确认检查只表示本轮检查结束，不表示设备已维修或恢复正常。

### 11.4 从当前位置重规划

`replan_mission` 复用 D 的 `plan_inspection`，只对尚未完成的目标规划：

- 不重置当前位置；
- 不重置或增加已走距离；
- 不重新加入已完成设备；
- 不遗忘当前关闭通道；
- 关闭通道后旧未来路线被替换，历史行走和完成记录保留；
- 重新开放后可以恢复对原不可达目标的规划。

### 11.5 状态与距离

任务状态：

| 状态 | 含义 |
| --- | --- |
| `active` | 有待检目标，且至少有一个可达 |
| `blocked` | 有待检目标，但当前全部不可达 |
| `completed` | 所有初始目标都已由人员确认 |
| `no_targets` | 输入没有疑似异常目标 |

距离分别显示：

- `walked_distance_m`：累计已走；
- `remaining_distance_m`：当前可达目标的剩余距离；
- `expected_total_distance_m`：仅在没有不可达目标时给出 = 已走 + 剩余，否则为 `null`。

只有全部目标确认后才显示“巡检完成”。全部不可达显示“受阻”，不能显示完成。

### 11.7 页面与 Agent

- 页面「③ 巡检规划」新增「巡检执行（模拟）」；
